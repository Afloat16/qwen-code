# Qwen #17123 R2-1 independent reproduction

Source: https://github.com/QwenLM/qwen-code/pull/17123#discussion_r4563563143

Baseline: f38593c135e451e180fcca8cbac245c727c501ae

**[Suggestion]** R2-1: The alias branch fires when a nested `security.folderTrust` object is present but lacks `enabled`, so `qwen serve` gates the workspace while the migration, the full loader and the daemon read trust **off** for the same file.

**Failure scenario:** a `$version`-less operator settings file `{"security":{"folderTrust":{"featureEnabled":true}},"folderTrustFeature":true}` (hand-edited after an older CLI wrote the dead nested key). `pickFastPathSettings` leaves `out.security` undefined — the nested branch only records a boolean `enabled` — so this branch sets `enabled: true` and `qwen serve` withholds the workspace's `.env`, `settings.env` and startup channels. The v1→v2 migration writes `enabled: true` in step 1 and then step 4 replaces `security.folderTrust` with the original nested object, leaving `enabled` undefined, so `loadSettings`, `isFolderTrustEnabled` and `readDaemonTrustPolicySnapshot` all read trust off. One file, two trust answers: the bootstrap enforces the gate and the runtime does not.

**Witness:**

```
PR f38593c1, exact file:
  FASTPATH security={"folderTrust":{"enabled":true}}
  MIGRATED={"security":{"folderTrust":{"featureEnabled":true}},"$version":2}, isFolderTrustEnabled=false
  DAEMON folderTrustEnabled=false, evaluate=trusted
alias hunk reverted to the merge base:
  FASTPATH security=undefined ; DAEMON false  (the two readers agree)
```

**Suggested fix:** take the alias only when the nested key is genuinely absent. `out.security === undefined` means "the nested branch produced a boolean", not "there is no nested `folderTrust`", so guard on a nested `security.folderTrust` object being present and skip the alias then; `folderTrust`-over-alias precedence stays as it is.

**Constraint:** the migration's nested precedence is the last-segment assignment in `setNestedPropertySafe` (`packages/cli/src/config/settingsUtils.ts:531`) — a nested `security.folderTrust` object replaces the migrated `enabled` rather than merging with it, so the fast path must not assume a merge the loader does not perform.

Add `{ security: { folderTrust: {} }, folderTrustFeature: true }` to the existing `it.each` ("keeps explicit folder-trust settings ahead of the feature alias") expecting `security?.folderTrust?.enabled` to be `undefined`; remove the nested-present guard and that case must go red.
